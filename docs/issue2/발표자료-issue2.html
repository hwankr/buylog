핵심 코드 리뷰 ① — Gemini 멀티모달 OCR

lib/services/ocr_service.dart

3-1. responseSchema — 응답 구조 강제

Gemini가 항상 동일한 JSON 구조를 반환하도록 responseSchema를 명시합니다. 이 없이는 자유 형식 텍스트가 반환돼 파싱 실패가 잦습니다.

static const _responseSchema = {
  'type': 'object',
  'properties': {
    'storeName': {'type': 'string'},
    'date':      {'type': 'string', 'nullable': true},
    'items': {
      'type': 'array',
      'items': {
        'type': 'object',
        'properties': {
          'name':  {'type': 'string'},
          'price': {'type': 'integer'},
        },
        'required': ['name', 'price'],
      },
    },
  },
  'required': ['storeName', 'items'],
};

3-2. analyzeImage() — 메인 OCR 진입점

static Future<OcrResult?> analyzeImage(Uint8List imageBytes) async {
  final apiKey = dotenv.env['GEMINI_API_KEY'] ?? '';
  if (apiKey.isEmpty) return null;

  final base64Image = base64Encode(imageBytes);         // 이미지 → Base64
  final url = 'https://generativelanguage.googleapis.com/v1beta/'
               'models/gemini-2.5-flash:generateContent?key=$apiKey';

  final body = {
    'contents': [{
      'parts': [
        {'text': '이 영수증에서 상점명, 날짜, 모든 단품 상품(합계/결제금액 제외)을 추출해.'},
        {'inline_data': {'mime_type': 'image/jpeg', 'data': base64Image}},
      ],
    }],
    'generationConfig': {
      'temperature': 0,                    // 결정론적 출력
      'maxOutputTokens': 2048,
      'responseMimeType': 'application/json',
      'responseSchema': _responseSchema,    // 구조 강제
    },
  };
  // ... HTTP POST → JSON 파싱 → OcrResult 반환
}
✅
temperature: 0 설정 이유 OCR은 창의적 응답이 필요 없고 영수증 내용을 정확히 옮겨야 합니다. temperature를 0으로 설정하면 동일 입력에 항상 동일한 결과를 보장합니다.

핵심 코드 리뷰 ② — Fallback 파싱 체계

lib/services/ocr_service.dart

4-1. ScanScreen 호출 흐름

①
Gemini 멀티모달 직접 파싱 Main Path
OcrService.analyzeImage(imageBytes) — 이미지 → OcrResult 직접 반환
②
Google Cloud Vision API Fallback 1
analyzeImage 실패 시 → OcrService.extractText(imageBytes) → raw 텍스트 추출
③
Gemini 텍스트 파싱 → Regex Fallback 2
raw 텍스트 → OcrService.parseReceiptText() → Gemini 텍스트 파싱 또는 Regex 3-pass
// ScanScreen._startOcr()
OcrResult? result = await OcrService.analyzeImage(_imageBytes!);

if (result == null) {                          // Fallback 진입
  final rawText = await OcrService.extractText(_imageBytes!);
  if (rawText == null || rawText.trim().isEmpty) {
    /* 에러 표시 */ return;
  }
  result = await OcrService.parseReceiptText(rawText);
}

4-2. 날짜 형식 정규화 — _parseFlexibleDate()

Gemini가 반환하는 날짜 형식이 영수증마다 달라서 DateTime.tryParse()만으로는 실패합니다.

static DateTime? _parseFlexibleDate(String? raw) {
  if (raw == null) return null;

  // "2026.04.08" → "2026-04-08"
  var normalized = raw
    .replaceAll('년 ', '-').replaceAll('월 ', '-').replaceAll('일', '')
    .replaceAll('.', '-').replaceAll('/', '-').trim();

  return DateTime.tryParse(normalized);
  // 처리 가능: "2026.04.08" / "2026/04/08" / "2026년 4월 8일"
}
⚠️
기존 Regex 파싱의 한계 영수증은 표 형태(가격이 상품명과 다른 줄에 있음)인 경우가 많아 "같은 줄에 가격 있음"을 전제한 Regex는 0개 검출 오류가 발생했습니다. Gemini는 레이아웃을 시각적으로 이해하므로 이 문제가 해결됩니다.

5-2. getUserMedia 카메라 오버레이 핵심 로직

Future<Uint8List?> pickFromCameraWeb() async {
  try {
    // 후면 카메라 스트림 요청
    final stream = await window.navigator.mediaDevices
        .getUserMedia(MediaStreamConstraints(
          video: MediaTrackConstraints(facingMode: 'environment'),
          audio: false,
        ));

    // 풀스크린 오버레이 생성
    final overlay = document.createElement('div') as HTMLDivElement
      ..style.position  = 'fixed'
      ..style.inset     = '0'
      ..style.zIndex    = '9999'
      ..style.background = '#000';

    final video = document.createElement('video') as HTMLVideoElement
      ..srcObject = stream
      ..autoplay  = true
      ..style.width = '100%'
      ..style.height = '100%'
      ..style.objectFit = 'cover';

    // 📸 촬영 버튼: canvas에 현재 프레임 캡처 → base64 → Uint8List
    captureBtn.onClick.listen((_) {
      final canvas = HTMLCanvasElement()
        ..width  = video.videoWidth
        ..height = video.videoHeight;
      canvas.context2D.drawImage(video, 0, 0);
      final dataUrl = canvas.toDataURL('image/jpeg', 0.92);
      final bytes   = base64Decode(dataUrl.split(',')[1]);
      completer.complete(bytes);      // OCR로 전달
    });
  } catch (e) {
    return _fileFallback();  // 권한 거부 시 파일 선택기로 fallback
  }
}
💡
dart:html 대신 package:web 사용 이유 Flutter 팀이 dart:html을 deprecated 예정으로 공식 발표. package:web + dart:js_interop이 공식 후속 패키지이며, 향후 Wasm 컴파일에도 호환됩니다.

기술적 의사결정 및 트레이드오프

6-1. OCR 엔진 선택: Gemini vs OpenAI vs Regex

방식정확도비용레이턴시결정
Regex 파싱만 낮음 (비정형 실패) 무료 즉시 Fallback 전용
Vision + Regex 중간 (표 형태 실패) API 1회 1~2초 Fallback 2
OpenAI GPT-4o 높음 높음 (Input $2.5/MTok) 2~4초 비용 과다
Gemini 2.5 Flash 높음 낮음 (무료 티어 포함) 1~2초 채택 ✓

6-2. 웹 카메라: getUserMedia vs image_picker

BEFORE — image_picker (웹)
  • 브라우저에서 파일 선택기(갤러리)만 열림
  • 실시간 카메라 미리보기 불가
  • 모바일 웹에서 후면 카메라 지정 불가
  • 사진 촬영 UX 없음
AFTER — getUserMedia (웹)
  • 실시간 카메라 스트리밍 미리보기
  • 후면 카메라 강제 지정 (facingMode: environment)
  • 촬영 버튼으로 즉시 캡처
  • 권한 거부 시 파일 선택기로 안전하게 fallback

6-3. CORS 이슈 — 웹 환경의 제약

⚠️
브라우저에서 외부 API 직접 호출 시 CORS 차단 네이버 쇼핑 API, OpenAI API 등은 브라우저 CORS 정책에 의해 웹에서 직접 호출이 차단됩니다. 현재는 개발 환경에서 --disable-web-security 플래그로 우회, 출시 전 서버 프록시 구현 예정. Android/iOS 네이티브 앱은 CORS 제약 없이 정상 동작합니다.

Q&A 예상 질문

예상 질문답변 포인트
Gemini API 비용이 걱정되지 않나요? Gemini 2.5 Flash는 무료 티어(분당 15회, 일 1,500회)가 있어 학교 프로젝트 규모에서 비용 발생 없음. 유료 전환 시에도 GPT-4o 대비 약 10배 저렴.
영수증 종류마다 다 잘 되나요? Gemini는 이미지를 시각적으로 이해하므로 표 형태, 열 배치, 다양한 폰트 모두 처리. Fallback 체계로 실패 시에도 안전하게 처리.
API 키가 앱에 포함되어 있으면 보안 문제 아닌가요? 현재는 개발 단계로 .env 파일에 저장하고 gitignore 처리. 출시 전 서버 프록시 구조로 전환 예정.
웹 카메라는 모바일에서도 되나요? 모바일 Chrome에서도 getUserMedia가 동작하며, facingMode: environment로 후면 카메라 직접 실행됨. 네이티브 앱은 ImagePicker 카메라 모드 사용.
🎯
핵심 메시지 기존 Regex 기반 OCR의 한계를 Gemini 멀티모달로 극복해 비정형 영수증 파싱 정확도를 크게 향상시켰으며, Flutter Web의 카메라 제약을 Web API로 직접 해결해 자연스러운 촬영 경험을 구현했습니다.
